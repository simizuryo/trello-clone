# 00. 前提知識: AWS・IaC・Terraformとは

AWS/Terraformが初めての人向けに、このデプロイ作業で出てくる概念を最低限まとめる。すでに知っている用語は読み飛ばしてよい。

## AWSとは

Amazon Web Services。AWSは「サーバー」「データベース」「ネットワーク」などをインターネット経由で必要な分だけ借りられるサービス群(クラウド)。自分でサーバー機材を買う代わりに、AWSが持っている巨大なデータセンターの一部を時間単位・使用量単位で借りる。

このプロジェクトは段階的に構築を進める(詳細は[03-architecture.md](03-architecture.md))。現在のPhase 1(EC2のみ)で使うAWSサービス:

| サービス | 役割 |
|---|---|
| VPC | AWS上に作る自分専用の仮想ネットワーク |
| EC2 | 仮想サーバー(コンピュータ)を借りるサービス。ここではフロントエンド画面+バックエンドAPIを同梱したDockerコンテナを直接動かす |
| ECR | 自分たちのDockerイメージを保管する倉庫(DockerHubのAWS版) |
| Systems Manager(SSM) | SSHキーなしでEC2にシェル接続・コマンド実行できるサービス |
| IAM | 「誰が」「何を」できるかを管理する権限の仕組み |

今後のフェーズで追加予定のサービス:

| サービス | 役割 | 追加予定のフェーズ |
|---|---|---|
| RDS | マネージドなPostgreSQLデータベース | Phase 2 |
| Secrets Manager | パスワードなどの秘密情報を安全に保管する場所 | Phase 2(RDSのパスワード管理用) |
| S3 / CloudFront | フロントエンドをEC2から分離して配信する場合の構成(検討中) | Phase 3(検討中) |

## なぜマネジメントコンソール(画面操作)を使わないのか

AWSマネジメントコンソールはブラウザでポチポチ操作する画面。手軽だが以下の問題がある。

- **再現性がない**: 「どのボタンをどの順で押したか」は記録に残りづらく、同じ環境をもう一度作るのが大変
- **レビューできない**: 変更内容をコードのように差分(diff)で確認できない
- **消し忘れが起きやすい**: 学習用に作ったリソースを消し忘れて課金が続く、ということが起きやすい

これを解決するのが **IaC(Infrastructure as Code)** という考え方。

## IaC(Infrastructure as Code)とは

インフラ構成(サーバーやネットワークの設定)を、手順書ではなく**コード(テキストファイル)として記述**し、それを実行することでインフラを構築・変更する手法。アプリのソースコードと同じように、

- Gitでバージョン管理できる
- 変更をPull Requestでレビューできる
- 同じコードを実行すれば同じ環境が再現できる
- 「今どんな状態か」がコードを読めばわかる

というメリットがある。このプロジェクトではIaCのツールとして **Terraform** を使う。

## Terraformとは

HashiCorp社が開発しているOSSのIaCツール。特徴:

- **HCL(HashiCorp Configuration Language)** という専用の言語で「欲しい最終状態」を宣言的に書く(手順ではなく結果を書く、という発想)
- AWS以外にもGCP・Azureなど多数のクラウドに対応する共通の書き方ができる
- 現在のインフラの状態を **tfstate(ステートファイル)** というファイルに記録し、次にコードを変更したときに「何を追加/変更/削除すればよいか」を自動的に計算する

### 中心となる3つの操作

| コマンド | 何をするか |
|---|---|
| `terraform init` | 使用するプロバイダ(AWS用プラグイン等)をダウンロードして初期化する |
| `terraform plan` | 今のコードと実際のAWS上の状態を比較し、「何を作る/変える/消すか」を **実行せずに** 表示する |
| `terraform apply` | `plan`の内容を確認したうえで、実際にAWS上にリソースを作成・変更・削除する |

`apply`は実際に課金対象のリソースを作る操作なので、必ず`plan`の内容を読んでから実行する。

### 主要な用語

- **provider(プロバイダ)**: どのクラウド/サービスを操作するかの設定。ここでは`hashicorp/aws`
- **resource(リソース)**: 実際に作成する個々の部品。例: `aws_vpc`, `aws_db_instance`
- **variable(変数)**: リソース定義の中で使う可変値。環境ごとに変えたい値をここにまとめる
- **output(出力)**: `apply`後に画面に表示したい値。例: バックエンドのURL
- **state(ステート)**: 「今Terraformが管理しているリソースの実際の状態」を記録したファイル(`terraform.tfstate`)。このプロジェクトではローカルに保存する(詳細は[02-terraform-setup.md](02-terraform-setup.md))

## このプロジェクトでの位置づけ

`terraform/`ディレクトリの`.tf`ファイル群が「AWS上にどんなリソースを作るか」の設計図。これをClaude Code(AI)がAWS CLIの認証情報を使って`terraform apply`し、実際のAWS環境を構築・更新する。マネジメントコンソールを手で触ることは基本的にない(IAMユーザー作成などTerraformの前提となる最初の一部の手順を除く)。
